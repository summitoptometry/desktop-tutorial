# 版本管理系统功能总结

## ✅ 已实现的功能

### 1. 自动版本创建 ✅

**功能**：npm build 完成后自动创建版本文件夹

**实现**：
- 修改 `package.json` 添加 `postbuild` 脚本
- 创建 `version_builder.py` 版本构建器
- 自动生成版本名称：`YYYYMMDD-N`（如：20260110-1）

**使用**：
```bash
npm run build
# 自动创建 versions/20260110-1/ 文件夹
```

### 2. 版本文件夹管理 ✅

**功能**：每个版本包含完整的打包产物

**实现**：
- 版本文件夹存储在 `versions/` 目录
- 版本信息记录在 `versions/version_log.json`
- 支持查看、删除版本

**结构**：
```
versions/
├── 20260110-1/          # 版本文件夹
│   ├── index.html
│   ├── assets/
│   └── static/
├── 20260110-2/          # 另一个版本
└── version_log.json     # 版本列表
```

### 3. 版本选择部署 ✅

**功能**：部署时选择使用哪个版本文件夹

**实现**：
- 创建 `deploy_v2.py` 新部署脚本
- 支持 `--version` 参数选择版本
- 如果不指定，使用最新版本

**使用**：
```bash
# 部署最新版本
.\deploy.bat

# 部署指定版本
.\deploy.bat --version 20260110-1
```

### 4. 本地日志记录 ✅

**功能**：所有部署日志记录在本地

**实现**：
- 部署日志记录在 `versions/deploy_log.json`
- 包含版本信息、部署时间、文件列表等
- 版本状态更新记录在 `version_log.json`

**日志内容**：
- 版本名称
- 部署时间
- 部署描述
- 服务器信息
- 文件数量和列表

### 文档文件

## 🔄 工作流程

```
1. npm run build
   ↓
2. 自动执行 postbuild 脚本
   ↓
3. 创建版本文件夹（如：20260110-1）
   ↓
4. 复制 dist 内容到版本文件夹
   ↓
5. 更新 version_log.json
   ↓
6. 部署时选择版本
   ↓
7. 从版本文件夹上传到服务器
   ↓
8. 更新版本状态为 "deployed"
   ↓
9. 记录部署日志到 deploy_log.json
```

## 📊 版本命名规则

格式：`YYYYMMDD-N`

- **YYYYMMDD**：日期（年-月-日）
- **N**：该日期的序列号（从1开始）

示例：
- `20260110-1` - 2026年1月10日第1个版本
- `20260110-2` - 2026年1月10日第2个版本
- `20260111-1` - 2026年1月11日第1个版本

## 📝 日志文件说明

### version_log.json

版本信息日志，包含所有版本的基本信息：

```json
{
  "versions": [
    {
      "name": "20260110-1",
      "path": "路径",
      "status": "deployed",
      "created_at": "时间",
      "deployed_at": "时间",
      "file_count": 45
    }
  ]
}
```

### deploy_log.json

部署历史日志，包含所有部署记录：

```json
{
  "deployments": [
    {
      "version_name": "20260110-1",
      "deployed_at": "时间",
      "description": "描述",
      "server_path": "服务器路径",
      "files_count": 45
    }
  ]
}
```

## ✨ 优势

1. ✅ **版本管理**：每个版本都有独立的文件夹，方便管理和回滚
2. ✅ **自动化**：build 后自动创建版本，无需手动操作
3. ✅ **日志完整**：所有操作都有日志记录，可追溯
4. ✅ **本地存储**：日志在本地，不依赖服务器
5. ✅ **灵活部署**：可以选择任意版本进行部署
